T01 turned `packages/contracts` into a real, tested Zod contract package and added fail-fast environment validation to both apps. T02 added a new shared `packages/domain` package with pure, unit-tested distance/sort/filter/favourite functions. T03 replaced the bare T00 placeholder pages with a real responsive application shell. T04 made the Discovery page capable of resolving an actual, usable search origin (current-location + manual lat/lng, backed by a `SearchCenterSchema` in `packages/contracts`). T05 gave `apps/api` a real, working cafe-search endpoint: `POST /api/v1/cafes/search` validates the request via T01's `CafeSearchRequestSchema`, delegates to a `GooglePlacesProvider` (Google Places API New `searchNearby`, minimal field mask, injectable-fetch for testability) that maps Google's raw response to Bean Stalker's `Cafe` contract and computes `distanceMeters` by reusing T02's `haversineDistanceMeters` (no duplicate formula), and maps provider/network failures to the Error Catalog's stable envelope. Never calls Google with an invalid request; never leaks the server key or raw provider payloads. T06 added a `CafeMap` component (`apps/web/src/map/`) that loads the Google Maps JavaScript API via a hand-written, dedicated loader (`googleMapsLoader.ts`, using the current `loading=async&callback=` script pattern and `google.maps.importLibrary('maps')` — not the deprecated synchronous bootstrap, not a third-party React wrapper), centers a real `google.maps.Map` on the same resolved `SearchCenter` that `LocationSelector` displays (the two now share one `useLocation()` instance lifted up to `DiscoveryPage`), re-centers via `setCenter` on location change rather than recreating the map, and renders accessible loading/no-center/error status text instead of raw Google errors or a crash. It implements no markers, no cafe fetching, and no filter/sort UI — that is explicitly T07's scope. It uses only the browser-visible `VITE_GOOGLE_MAPS_BROWSER_KEY`, never the server key.

T07 connected the three prior subsystems into a working discovery flow. `apps/web/src/search/` holds a single browser→API boundary (`apiClient.ts` — `searchCafes(request, signal)`, outbound + inbound Zod validation, typed `CafeSearchError`, never a raw provider/framework payload) and a cost-safe TanStack Query hook (`useCafeSearch.ts`): one request per committed `SearchCenter`, `retry: false`, all automatic refetch (focus/reconnect/mount/interval) disabled, 5-minute `staleTime`, stable primitive query key — rerenders, map pan/zoom and card/marker selection never issue a provider request (RM0 / [[ADR-007 Cost-Safe Search Orchestration]]). `apps/web/src/cafes/` renders the accessible primary result surface (`CafeList`/`CafeCard` — honest "No rating data"/"Hours unavailable" labels, Maps link only when present, `aria-pressed` selection with a non-colour cue) and `SearchStatePanel` (distinct no-location / loading / empty / retryable-error states — empty is never conflated with failure). `CafeMap` gained `AdvancedMarkerElement` markers via a non-React `MarkerLayer` adapter (one marker per `placeId`, keyed reconciliation, `gmp-click` → selection, selected pin restyled + `panTo`, full listener cleanup) and now requires `VITE_GOOGLE_MAPS_MAP_ID`. `DiscoveryPage` owns `selectedCafeId` (reconciled to the current result set by derivation, not effect-setState); list and map share one `Cafe[]` and one selection — clicking either selects the other. A map failure still leaves the list fully usable. `apps/api` gained a `CAFE_PROVIDER` env switch: `FixtureCafeProvider` (dev/test only) serves the committed fixture through the *same* normalization as the live provider — `GooglePlacesProvider` is untouched. The stale-response race ([[Test Case Catalog|TC-SEARCH-003]]) is covered by a deterministic deferred-promise test; no automated test loads live Google Maps or Places.

T09 added local sort/filter controls that operate **entirely on the already-fetched `Cafe[]`**. `apps/web` now depends on `@bean-stalker/domain` (`workspace:*`) for the first time. `apps/web/src/cafes/filterState.ts` holds `DiscoveryFilters { minRating, openNowOnly, sortBy }`, the defaults (`minRating: 0`, off, `DISTANCE` — hides nothing, preserves T07 order), the bounded min-rating choices (Any / 3+ / 3.5+ / 4+ / 4.5+), and a pure `applyDiscoveryFilters(cafes, filters)` = `sortCafes(filterCafes(cafes, …), sortBy)` — filter then sort, delegating entirely to T02, mutating nothing. `FilterBar.tsx` is the native-control UI (`<select>` × 2, a checkbox, a Reset button disabled at defaults). `DiscoveryPage` holds `filters` as plain `useState`, derives `displayedCafes` with `useMemo`, and passes it (plus one shared `selectedCafeId`) to both `CafeList` and `CafeMap` — list and map always show the same set. Selection reconciles by render-derivation against `displayedCafes` **and** the FilterBar change handler drops a hidden selection permanently, so relaxing a filter never silently re-selects. A filter that removes every cafe shows "No cafes match your current filters" — distinct from the API-empty "No cafes were found near this location". `MarkerLayer.setSelected` now only pans on a genuine selection change (a re-sort with the same cafe selected does not move the map). **RM0:** no filter/sort value reaches `useCafeSearch`, the TanStack Query key, or the `CafeSearchRequest` — every control change issues 0 provider requests (test- and e2e-enforced). [[Open Questions|OQ-008]] resolved: [[Ranking and Filtering Rules]] v1.1 states the rating tie-break explicitly (rating DESC → `userRatingCount` DESC → distance ASC → stable), confirming T02.

T10 added browser-local favourites. `apps/web/src/favorites/` holds `favoritesStorage.ts` (the one owner of the `bean-stalker:favorites` key — `readFavoriteStore()` treats storage as untrusted: missing / bad JSON / wrong shape / unsupported `version` / thrown Storage exception all degrade to an empty store, and a bad read is never rewritten; `writeFavoriteStore()` returns `{ ok }` instead of throwing), a `FavoritesProvider` (hydrates once via a lazy `useState` initializer, shares `favoriteIds`/`favorites`/`toggleFavorite`/`removeFavorite`/`persistenceError`, **persist-then-commit** — the UI only flips to "saved" if the `localStorage` write succeeded), `useFavorites`, `FavoriteButton` (a native `<button aria-pressed>` with an "Add/Remove `<cafe>` …" accessible name and a "Save/Saved" text label, rendered as a **sibling** of the card select button — the T07 card was restructured into a shared control-free `CafeSummary` plus sibling controls so nothing interactive is nested), and `FavoritePersistenceNotice` (a bounded `role="alert"` in `AppShell`). `FavoritesPage` is now real: reads only the context, no location/search/map, semantic `<ul aria-label="Saved cafes">` of snapshot summaries with per-item remove and a page-level staleness/local-only note, and a distinct accessible empty state. All favourite state is browser-local — Fastify, Google and the search layer never see it (no `useQuery`/`useMutation` wrapper; `apps/web/src/favorites/` has zero references to `searchCafes`/`useCafeSearch`/the query key). **RM0:** every favourite action is local state + one `localStorage` write, 0 provider requests (test- and e2e-enforced). Favouriting a cafe never selects it or pans the map; a favourite hidden by a T09 filter stays saved and reappears favourited when the filter is relaxed.

The pre-T08 hardening milestone (H02–H05, [[ADR-008 Metered Provider Cost Controls]]) added server-side privacy and cost controls, all fixture/mock-verified with **zero** real Google traffic. **H02:** `apps/api/src/logging.ts` configures Fastify's logger to emit only `reqId` + method + path (query strings stripped) + status + latency + bounded error codes — the client IP (`remoteAddress`), request body / `SearchCenter` / coordinates, credentials and raw provider payloads are never logged, and the custom `err` serializer strips any attached property from a thrown error. **H03:** a hand-rolled `FixedWindowRateLimiter` (injectable clock) limits `POST /api/v1/cafes/search` per client IP (`SEARCH_RATE_LIMIT_MAX`/`WINDOW_MS`, provisional 10/min) → **429 `RATE_LIMITED`** + `Retry-After`; the IP is an ephemeral in-memory key only; `/health` is not limited. **H04:** a `ProviderUsageGuard` interface (`tryConsume`/`getStatus`, atomic check-and-consume) with `InMemoryProviderUsageGuard` (UTC-month period, injectable clock) and `UnlimitedProviderUsageGuard` (fixture mode). One unit is consumed *before* each provider attempt and is *not* refunded on failure; validation/rate-limit rejections consume nothing and never reach the provider; exhaustion → **503 `PROVIDER_CAPACITY_EXHAUSTED`**. `PROVIDER_MONTHLY_REQUEST_LIMIT` is validated config, **required in `live` mode**. The in-memory guard is explicitly **not** a production financial hard cap — [[Known Blockers|BLK-004]]. **H05:** 429 and 503 are distinct shared error codes with distinct bounded frontend copy ("You're searching too quickly" / "Live cafe search is temporarily unavailable"); neither auto-retries (the query already sets `retry: false`); the resolved location, favourites and map/list isolation are preserved. The route pipeline is `validate → rate limit → usage guard → provider`. `apps/api` is wired through `buildApp` options (`usageGuard`, `searchRateLimiter`, `logger`) so tests inject strict configs.

**H06 (secrets & config, [[ADR-009 API Security Posture]]):** every env var is inventoried and classified in [[Environment Contract]] — the **only** secret is `GOOGLE_PLACES_SERVER_KEY`; the browser Maps key/Map ID are public config by design. Both `GOOGLE_PLACES_SERVER_KEY` and `PROVIDER_MONTHLY_REQUEST_LIMIT` are `optional()` at the schema level and **required via `superRefine` when `CAFE_PROVIDER=live`** — live mode fails closed, fixture mode needs no credential. A shared `HttpOriginSchema` (`packages/contracts`) validates `WEB_ORIGIN` and `VITE_API_BASE_URL` as bare origins (trailing slash normalised; path/query/non-http rejected). `GOOGLE_PLACES_TIMEOUT_MS` is now bounded (100–30000, default 10000). `scripts/check-frontend-dist-secrets.mjs` runs inside `apps/web`'s `build` and fails it if `apps/web/dist` contains `GOOGLE_PLACES_SERVER_KEY` / `X-Goog-Api-Key` / `places.googleapis.com` (the browser key/Map ID are expected and not flagged). Git history verified clean of real key patterns. There is no root `.env` — each app owns its own `.env.example`.

**H07 (backend security, [[ADR-009 API Security Posture]]):** `apps/api/src/security.ts` adds an `onSend` hook setting `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `X-Frame-Options: DENY` on every response, and a `setNotFoundHandler` returning the canonical envelope with code **`NOT_FOUND`** (404) for unknown routes and unsupported methods — Fastify's default 404 would echo the route pattern. `Fastify({ bodyLimit: 16 KiB, requestTimeout: 20 s })` — an over-limit body is rejected during parsing, **before** the rate limiter / usage guard / provider (`provider = 0`, `usage = 0`). CORS stays a strict single configured origin (`@fastify/cors` string — never reflects an arbitrary `Origin`). `trustProxy` stays at its safe default; deployment must define the trusted hop (BLK-003). No auth/sessions/CSRF machinery — the API has no accounts, cookies or mutation endpoints. Shared error code `NOT_FOUND` added to `packages/contracts` + [[Error Catalog]] + `openapi.yaml`.

**H08 (mobile & accessibility QA, [[UX Contract]] §"H08 baseline"):** a corrective-polish pass on the existing fixture-backed app — no new features, no backend change. Fixes: `--color-accent` darkened `#b5651d → #a85a17` (the old value scored 4.33:1 on white / 4.16:1 on the page ground — below WCAG 2.1 AA 4.5:1 for the link/button text using it; the selected map-pin hex was updated to match); the "Open now only" checkbox enlarged to 1.5 rem (24 px) for the WCAG 2.2 target-size minimum; standalone links ("Open in Google Maps", the 404 home link) given vertical tap padding. Location errors (denied permission / invalid coordinates) now render in an assertive `role="alert"` — split from the polite `role="status"` progress line — and invalid manual coordinates set `aria-invalid` + `aria-describedby` on both coordinate inputs (`ManualLocationForm` gained `errorMessageId`/`invalid` props). The API-empty search result gained `role="status"` so it is announced. New dev-only dependency `@axe-core/playwright` (excluded from the browser bundle) drives `tests/e2e/accessibility.spec.ts` — a zero-violation scan of 9 representative states (`.cafe-map__surface` excluded as third-party).
